## الفكرة

صاحب المحل يحچي ويا محفظته مثل ما يحچي ويا صانعه: «بعت 3 كراتين ببسي لأبو حسين بالدين»، «شكد ربحت هالأسبوع؟»، «ذكّر أم زينب». **النموذج يفهم ويشرح، والدفتر يحسب كل رقم**، وأي شي يكتب بالدفتر أو يحرّك فلوس ما يصير إلا بموافقته.

> الدين ينسجل ← الزبون يأكده من محفظته ← يوصله تذكير برابط دفع ← يسدد بضغطة ← الدفعة تتطابق ويا الدين وحدها

| الميزة | شنو تسوي |
|---|---|
| 🗣️ **يحچي عراقي** | قيد أو سؤال بالصوت أو الكتابة وباللهجة. يكتب اللي سمعه «سمعتك: … صح؟» قبل أي تنفيذ |
| 🧮 **الأرقام من الكود** | النموذج ما يحسب ولا رقم. المدقق يرفض أي رقم ما رجعته أداة، وكل رقم بالجواب ينضغط ويبين قيوده |
| 🤖 **وكيل للأسئلة المفتوحة** | «ليش ربحي نزل؟» و«شلون أدبّر الإيجار؟» بأدوات قراءة بس، وحد 5 خطوات. يقترح، وإنت تقرر |
| 🛒 **الزبون عنده وكيل هم** | «اريد 2 كيلو سكر وكارتون ببسي» تصير سلة بأسعار المحل، والطلب يوصل لهاتف صاحب المحل |
| 🛡️ **حماية من الاحتيال** | 22 إشارة تنفحص قبل كل تحويل، وشاشة توعية للخطر العالي. القرار الأخير لصاحب الفلوس |
| 📈 **يكبّر المحافظ الإلكترونية** | كل دين وتذكير وطلب يصير حركة بالمحفظة، وكل زبون يوصله تذكير هو مستخدم جديد إلها |

> كل الميزات بالتفصيل، شاشة شاشة: [الميزات](docs/FEATURES.md)

## جربه خلال دقيقة

**على Windows بدون أوامر:** افتح مجلد **«ملف التشغيل»** واضغط **«تشغيل المحاكاة»**. يتأكد من Node.js، ويشغّل الخادم، ويفتح الموقع بـMicrosoft Edge، لأن بيه الصوت العراقي «باسل» و«رنا».

**أو بالأوامر**، على أي نظام:

<div dir="ltr">

```bash
git clone https://github.com/inkedo300-bot/zain-agent.git
cd zain-agent
node server.js        # Node 18+, no dependencies → http://localhost:8080
```

</div>

**المفاتيح اختيارية.** بدونها كلشي يشتغل بالوضع الاحتياطي: محلل ثابت للهجة وقوالب جاهزة. وحتى يشتغل الذكاء الاصطناعي، انسخ <code dir="ltr">.env.example</code> باسم <code dir="ltr">.env</code> وحط بيه مفتاح Gemini المجاني، أو استخدم «إدخال المفاتيح» على Windows. ملف المفاتيح ما ينرفع لـGitHub أبداً.

> المفاتيح، والنماذج، والصوت، والاستضافة: [التشغيل](docs/SETUP.md)

## شلون يشتغل

القاعدة: **«الوكيل يفكّر، وسير العمل ينفّذ».** أي شي يكتب بالدفتر أو يحرّك فلوس يمشي بخطوات ثابتة ومختبرة. والوكيل يشتغل بس على الأسئلة المفتوحة، ويقرا بس، واللي يطلع منه اقتراحات.

```mermaid
flowchart RL
  U["صاحب المحل<br/>صوت أو كتابة"] --> P["الخصوصية<br/>الأسماء تصير رموز"]
  P --> R{"نوع الطلب"}
  R -->|"سؤال بسيط · قيد · أمر"| W["سير عمل ثابت"]
  R -->|"ليش؟ شلون أدبّر؟"| A["الوكيل<br/>أدوات قراءة · 5 خطوات"]
  W --> L[("الدفتر<br/>كل رقم بالكود")]
  A --> L
  L --> V{"المدقق"}
  V -->|"كل رقم من أداة"| OK["الجواب + أرقام تنضغط"]
  V -->|"رقم مخترع"| FB["جواب ثابت"]
  W --> C["بطاقة موافقة"]
  A -. "اقتراح" .-> C
  C --> M["المحفظة: إشعار للزبون أو المورد"]
```

* **النموذج ما يحسب:** حتى بتسجيل القيود، السعر من قائمة المحل والمجموع بالكود.
* **الخصوصية قبل النموذج:** أسماء الزباين وأرقامهم تتحول لرموز قبل أي طلب، وترجع بالجواب.
* **بدون نت أو مفتاح:** يشتغل بقواعد وقوالب، حتى العرض الحي ما يوگف.

> المعمارية، وبنك كلمات اللهجة، ودور كل ملف: [المعمارية](docs/ARCHITECTURE.md) · فحص التحويل وأوزانه: [كشف الاحتيال](docs/FRAUD.md)

## أنواع الأعطال

| العطل | التعامل |
|---|---|
| النموذج ما يرد، أو مشغول، أو خلصت الحصة | ينتظر مكان تحت حد الدقيقة، بعدها النموذج الثاني، بعدها المحلل الثابت والقوالب. ما يوگف |
| النموذج يخترع رقم أو ينسب كلام لزبون | المدقق يرفض الجواب ويطلع الجواب الثابت، والسبب يظهر بـ«خطوات الوكيل» |
| الصوت انسمع غلط | «سمعتك: … صح؟» قبل أي تنفيذ، وتگدر تصحح النص |
| الوكيل يطلب أداة كتابة أو دفع، أو يدور بحلقة | تنمنع، ويوقف بعد 5 أدوات ويجاوب سير العمل الثابت |
| محتال يدّعي إنه «دعم زين كاش» | فحص التحويل يطلع شاشة توعية، والإكمال يحتاج انتظار وتأكيد ورمز |
| زبون ينكر الدين | الدين يحتاج تأكيد من محفظته، والاعتراض يطلع تنبيه |

> كل الأعطال ويا التعامل وياها: [أنواع الأعطال](docs/FAILURE_MODES.md)

<summary><b>English summary</b></summary>
<br>

**Zain Agent (دفتر)** is an AI bookkeeping agent inside a mobile wallet for small Iraqi shops. The owner speaks or types in Iraqi Arabic: «sold 3 cartons of Pepsi to Abu Hussein on credit», «how much profit this week?», «remind Um Zainab».

- **The model understands; the code computes.** Every number comes from a ledger tool, a validator rejects any number a tool did not return, and every figure links to its ledger entries.
- **Workflow for actions, agent for questions.** Anything that writes or moves money runs as a fixed, tested workflow behind an approval card (money needs a PIN), with an audit log and undo. Open questions go to an agent with read-only tools and a 5-step limit that can only propose actions.
- **The customer has an agent too:** one sentence becomes a priced cart; debts are confirmed and paid from the customer's own wallet and matched automatically.
- **Transfer safety check:** 22 weighted signals before money leaves; rules decide, never the model, and the sender's age is never a signal.
- **Privacy:** customer names and phone numbers are masked before any model call.
- **Works offline:** without keys or internet it falls back to rules and templates.

Run `node server.js` (Node 18+, no dependencies) and open http://localhost:8080. All data is synthetic.

</details>
